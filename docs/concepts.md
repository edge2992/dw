# dw の考え方

用語は [GLOSSARY.md](../GLOSSARY.md) にまとめている。

## 作る → 書く → 見つける → 再開する

考えたいことを思いついたら、その場でトピックを一つ作る。作るときに聞かれるのは名前だけで、分類・状態・期限は聞かれない。そのまま書き始めてもいいし、何も書かずに置いておいてもいい。後で名前の一部で探して開き、同じ場所で続きを考える。

一時的なメモと長く続くプロジェクトを区別しない。メモが育っても、移行や「プロジェクトへの昇格」をする必要はない。

## 1 トピック = 1 ディレクトリ

```text
<root>/
└── 2026-10-24-調べ方を設計する/
    └── 調べ方を設計する.md      # メインノート
```

- ディレクトリ名は `<作成日>-<トピック名>`。日付は作った日を表し、一覧の並び順にも使う。
- メインノートのファイル名はトピック名と同じにする。Obsidian ではノートをファイル名で探したりリンクしたりするので、`README.md` や `STATE.md` のように全トピック共通の名前にすると、どのトピックのノートか見分けられない。
- トピック名は入力されたまま使う。日本語も空白も使える。パスや Obsidian のリンクを壊す文字が入っていたら、黙って書き換えずにエラーにする。
- ルートの中ではトピック名が重ならない。既にある名前を入力すると、新しく作らずにそのトピックを開く。
- dw が作るのはメインノートの `# トピック名` の 1 行だけ。`logs/`、`sources/`、追加の Markdown などは、必要になったときに自分で置く。dw はそれらの名前や有無を気にしない。

## filesystem が正本

一覧はルート直下のディレクトリをそのまま読んで作る。台帳もデータベースも持たない。Obsidian や `mkdir` で手作りしたディレクトリも、次に一覧を出したときに現れる。日付の付いていないディレクトリ（`読書を続ける/` など）は一覧の末尾に並ぶ。

dw が自分で持っている情報は「最後に開いたトピック」のパスだけで、これはキャッシュにすぎない。消えても、指しているディレクトリがなくなっていても、困ることはない。

dw が書き込むのは、新しくトピックを作るときだけ。既にあるトピックに書き足したり、名前を変えたり、移動したりはしない。

## 道具は薄く

dw は名前をパスに解決して表示するだけの道具で、選ぶのは fzf、移動するのはシェル関数の役目。エディタも Obsidian も起動しない。中身は普通のディレクトリと Markdown なので、Obsidian でもエディタでも `rg` でも Claude でも、同じものを扱える。

dw は思考法でもタスク管理でもない。考える型が必要になったら、メインノートに書けばいい。
